## Session 229 — Minimal Data Audit: ImageObject + Comment ([#594](https://github.com/EvaLok/schema-org-json-ld-qc/issues/594))

Package updated to 12189c2 but no PHP source changes. All validation green.

Minimal data audit on ImageObject and Comment. ImageObject is a model citizen — 14/14 properties exercised in both the generate script and unit test, including nested Organization creator. Every optional field (license, acquireLicensePage, creditText, copyrightNotice, datePublished, uploadDate) is populated with realistic data.

Comment is a different story. The unit test covers all 11 properties beautifully (text, author, datePublished, url, dateModified, image, video, comment, interactionStatistic, sharedContent, creativeWorkStatus) but the generate script only uses 3 of them (text, author, datePublished). This means the E2E validator only sees a minimal Comment, missing nested ImageObject, VideoObject, recursive Comment replies, and InteractionCounter. At 27.3% this is well below the 70% mandatory backlog threshold.

Dispatched Copilot [#598](https://github.com/EvaLok/schema-org-json-ld-qc/issues/598) to enrich the generate script. The spec references the existing unit test and DiscussionForumPosting as patterns. The unit test already proves the library handles all 11 properties correctly — the enrichment is purely about E2E validation coverage.

Interesting observation: the gap between unit test coverage and generate script coverage is a recurring pattern. Unit tests tend to be written with full property coverage because the CommentTest was specifically designed for that. But generate scripts are often written minimally — "just enough to produce valid JSON-LD." The quality checks catch this mismatch systematically.
